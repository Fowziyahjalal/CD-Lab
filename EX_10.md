# Experiment: Compiler Back-End — Generating 8086 Assembly from Three-Address Code using FLEX and BISON

## AIM
To write a program using FLEX and BISON to implement the back-end of a compiler which takes three-address code (TAC) as input and generates equivalent 8086 assembly language code.

## ALGORITHM
1. Use FLEX to tokenize each TAC line into identifiers and the operators `= + - * / ;`, passing tokens to BISON.
2. In BISON, define a grammar for assignment statements: `id = expr ;`
3. While reducing `expr`:
   - On the first operand, emit `MOV AX, operand`.
   - On `+`, emit `ADD AX, operand`; on `-`, emit `SUB AX, operand`.
   - On `*`, emit `MUL operand`; on `/`, emit `MOV DX,0` / `MOV BX,operand` / `DIV BX`.
4. When the full statement is reduced, emit `MOV result, AX`.
5. Repeat for every TAC statement in the input and print all generated instructions.
6. End.

## PROCEDURE
1. Create the FLEX file `backend.l` to tokenize identifiers and operators from TAC lines.
2. Create the BISON file `backend.y` with a grammar for TAC assignment statements, embedding 8086 `MOV`/`ADD`/`SUB`/`MUL`/`DIV` instruction generation directly in the semantic actions.
3. Compile and run:
   ```bash
   flex backend.l
   bison -d backend.y
   gcc lex.yy.c backend.tab.c -o backend -lfl
   ./backend
   ```
4. Input TAC statements such as: `t1 = a + b` followed by `x = t1`
5. View the generated 8086 assembly code.

## LOGIC / PSEUDOCODE

**Lexer (`backend.l`)** — tokenizes identifiers and operator/punctuation characters (no numeric literal support — this backend only handles identifier operands, consistent with TAC where operands are variables/temporaries):

```
RULE: letter followed by letters/digits
    yylval.str = COPY of matched text
    RETURN token ID

RULE: "="  -> RETURN '='
RULE: "+"  -> RETURN '+'
RULE: "-"  -> RETURN '-'
RULE: "*"  -> RETURN '*'
RULE: "/"  -> RETURN '/'
RULE: ";"  -> RETURN ';'

RULE: whitespace (space/tab/newline) -> IGNORE
RULE: any other single character      -> RETURN that character itself

FUNCTION yywrap()
    RETURN 1
```

**Parser (`backend.y`)** — parses `id = expr ;` and emits 8086-style instructions as a side effect of each reduction, using the accumulator register `AX` to hold the running result:

```
TOKEN (typed <str>): ID
NONTERMINAL (typed <str>): expr

PRECEDENCE:
    left '+' '-'
    left '*' '/'

GRAMMAR:
    stmt_list -> stmt_list stmt | stmt

    stmt -> ID '=' expr ';'
            { EMIT "MOV" $1 ", AX"            // store final accumulator value into the LHS variable
              EMIT blank line }

    expr -> ID
            {
                EMIT "MOV AX," $1              // load first operand into AX
                $$ = $1
            }
          | expr '+' ID
            {
                EMIT "ADD AX," $3              // AX = AX + operand
                $$ = $3
            }
          | expr '-' ID
            {
                EMIT "SUB AX," $3              // AX = AX - operand
                $$ = $3
            }
          | expr '*' ID
            {
                EMIT "MUL" $3                  // AX = AX * operand  (8086: DX:AX = AX * operand)
                $$ = $3
            }
          | expr '/' ID
            {
                EMIT "MOV DX, 0"                // clear DX (high half of dividend) before DIV
                EMIT "MOV BX," $3               // move divisor into BX (DIV needs a register/memory operand)
                EMIT "DIV BX"                   // DX:AX / BX -> quotient in AX, remainder in DX
                $$ = $3
            }

FUNCTION main()
    PRINT "Enter TAC statements (end with Ctrl+D):"
    CALL yyparse()
    RETURN 0

FUNCTION yyerror(message)
    PRINT "Syntax Error:" message
```

**Flow:** Every `expr` production models the 8086 accumulator-based instruction pattern directly: the first operand is loaded into `AX` with `MOV`, and every subsequent operator immediately emits the corresponding arithmetic instruction against `AX`. Division needs three instructions instead of one because the 8086 `DIV` instruction operates on the 32-bit dividend held across the `DX:AX` register pair, requires the divisor in a register (not an immediate/identifier), and produces the quotient in `AX` with the remainder left in `DX` — so `DX` must be zeroed first and the divisor moved into `BX`. Once the whole right-hand side has been reduced (leaving the computed value logically "in AX"), the top-level `stmt` rule emits a final `MOV <result>, AX` to store it into the target variable, followed by a blank line for readability between statements.

## PROGRAM

### Lexer — `backend.l`

```lex
%{
#include "backend.tab.h"
#include <string.h>
#include <stdlib.h>
%}

%%

[a-zA-Z][a-zA-Z0-9]*   { yylval.str = strdup(yytext); return ID; }

"="                     { return '='; }
"+"                     { return '+'; }
"-"                     { return '-'; }
"*"                     { return '*'; }
"/"                     { return '/'; }
";"                     { return ';'; }

[ \t\n]+                { /* skip whitespace */ }

.                       { return yytext[0]; }

%%

int yywrap() {
    return 1;
}
```

### Parser — `backend.y`

```yacc
%{
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
%}

%union {
    char *str;
}

%token <str> ID
%type <str> expr

%left '+' '-'
%left '*' '/'

%%

stmt_list:
    stmt_list stmt
    | stmt
    ;

stmt:
    ID '=' expr ';'
    {
        printf("MOV %s, AX\n\n", $1);
    }
    ;

expr:
    ID
    {
        printf("MOV AX, %s\n", $1);
        $$ = $1;
    }

    |
    expr '+' ID
    {
        printf("ADD AX, %s\n", $3);
        $$ = $3;
    }

    |
    expr '-' ID
    {
        printf("SUB AX, %s\n", $3);
        $$ = $3;
    }

    |
    expr '*' ID
    {
        printf("MUL %s\n", $3);
        $$ = $3;
    }

    |
    expr '/' ID
    {
        printf("MOV DX, 0\n");
        printf("MOV BX, %s\n", $3);
        printf("DIV BX\n");
        $$ = $3;
    }
    ;

%%

int main() {
    printf("Enter TAC statements (end with Ctrl+D):\n");
    yyparse();
    return 0;
}

int yyerror(char *s) {
    printf("Syntax Error: %s\n", s);
    return 0;
}
```

## COMPILATION

```bash
flex backend.l
bison -d backend.y
gcc lex.yy.c backend.tab.c -o backend -lfl
```

### Compiler Warnings Observed

The build succeeded but produced the same class of warnings seen in the type-checker and optimizer experiments:

```
backend.tab.c: In function 'yyparse':
backend.tab.c:977:16: warning: implicit declaration of function 'yylex'
backend.tab.c:1167:7: warning: implicit declaration of function 'yyerror'; did you mean 'yyerrok'?
```

These arise because `backend.y` doesn't forward-declare `int yylex(void);`, and `yyerror`'s parameter type (`char *s`) doesn't match the `const char *` signature Bison's generated caller expects. Both are harmless — the program still compiles, links, and runs correctly — but can be resolved by adding the prototype and correcting `yyerror`'s parameter type.

## SAMPLE RUN

`input.txt`:
```
t1 = a + b;
t2 = t1 - c;
t3 = t2 * d;
t4 = t3 / e;
x = t4;
```

Command:
```bash
./backend < input.txt
```

Output:
```
Enter TAC statements (end with Ctrl+D):
MOV AX, a
ADD AX, b
MOV t1, AX

MOV AX, t1
SUB AX, c
MOV t2, AX

MOV AX, t2
MUL d
MOV t3, AX

MOV AX, t3
MOV DX, 0
MOV BX, e
DIV BX
MOV t4, AX

MOV AX, t4
MOV x, AX

```

**Statement-by-statement mapping:**

| TAC statement | Generated 8086 assembly |
|---|---|
| `t1 = a + b;` | `MOV AX, a` / `ADD AX, b` / `MOV t1, AX` |
| `t2 = t1 - c;` | `MOV AX, t1` / `SUB AX, c` / `MOV t2, AX` |
| `t3 = t2 * d;` | `MOV AX, t2` / `MUL d` / `MOV t3, AX` |
| `t4 = t3 / e;` | `MOV AX, t3` / `MOV DX, 0` / `MOV BX, e` / `DIV BX` / `MOV t4, AX` |
| `x = t4;` | `MOV AX, t4` / `MOV x, AX` |

## RESULT
The FLEX and BISON programs were successfully compiled and executed. The program correctly translated a sequence of five three-address code statements — covering addition, subtraction, multiplication, and division — into equivalent 8086 assembly instructions using the `AX` accumulator (and `DX`/`BX` for the division case), verifying the working of the compiler back-end code generator.
